Relay: two jobs, one workshop, a visible A2A handoff.

A local teaching demo with invented venue data

Today I will show how one agent asks another agent to do a job. Our example is choosing a venue for a workshop. We can watch discovery, delegation, a clarification question and a returned recommendation. The venue data is fictional, but the agents exchange real HTTP requests through the official A2A SDK. Allow around ten minutes, including the live demonstration.

The job we want done

“Find a venue for a 30-person workshop.
Stay under AED 1,600. Explain the trade-off.”

The coordinator owns the request

It delegates the search, relays questions and reviews the recommendation.

The specialist owns the search

It checks the catalogue, asks what matters, and recommends a venue or rejects the brief.

The preferred budget is AED 1,400, but the absolute maximum is AED 1,600. These are different constraints. A slightly more expensive venue can be acceptable if it meets a meaningful preference. Both agents can use the same model provider. Different jobs, instructions and responsibilities create the delegation boundary.

A tool call and an agent delegation

Question Tool through MCP Agent through A2A
What is requested? A named operation and its inputs A goal with context and constraints
Who chooses the steps? The calling agent chooses the tool operation The receiving agent can choose how to work
What comes back? The operation's result Task status, a question, rejection or an artifact

In this demo, catalogue lookup is a direct function call. MCP is explained, not connected.

The key difference is the interface and responsibility. Asking a tool to look up venues specifies an operation. Asking a specialist to find a suitable venue delegates a job. A tool may still contain complex logic or AI, and MCP can support richer interactions. Do not reduce the distinction to whether something is intelligent or takes a long time. Sources: https://modelcontextprotocol.io/docs/learn/architecture and https://a2a-protocol.org/latest/specification/

Two services, separate responsibilities

Venue specialist · port 8781

The handoff crosses an HTTP boundary using A2A 1.0 JSON-RPC.

Official @a2a-js/sdk 1.3.0 · Two local services in one Node.js process

The coordinator never calls the specialist executor as an internal framework handoff. It uses the A2A client and actual HTTP. This demonstrates the communication boundary locally. It does not establish interoperability with another company's agent or certify complete protocol conformance. Source: docs/ARCHITECTURE.md and src/app.mjs.

Discovery begins with an Agent Card

The coordinator knows an address.
It reads what the specialist offers before delegating.

GET /.well-known/agent-card.json

  1. IdentityWhich agent is this?
  2. SkillsDoes it offer venue selection?
  3. InterfaceWhere and how should we send the task?

Known-address discovery. This demo does not use a search engine or agent registry.

An Agent Card is machine-readable information describing an agent and its capabilities. Discovery here means reading a configured specialist address, not finding any agent anywhere on the internet. The UI's protocol inspector shows the actual response. Sources: src/protocol/card.mjs and https://a2a-protocol.org/latest/topics/agent-discovery/

A task has a continuing identity

Exchange What happens
SendMessage The coordinator delegates a structured workshop brief.
GetTask It follows progress using the returned task ID.
input-required The specialist asks for a missing budget or priority.
SendMessage The reply continues the same task and context.
completed + artifact The specialist returns a recommendation for review.
These are the main exchanges, not a pasted live transcript. The inspector contains the actual traffic for each run. A task can also be rejected, fail or be cancelled. Task IDs distinguish work items. Context IDs connect related work. A2A standardizes their exchange, while our brief schema remains application-specific. Source: src/agents/coordinator.mjs and docs/ARCHITECTURE.md.

Clarification changes the decision

“What matters most: a quieter room,
separate breakout rooms, or keeping costs down?”

Choose breakout rooms

Harbor Hall offers two rooms for group work, with a higher price and moderate noise.

Choose a quieter room

Cedar Room offers a quieter setting below the preferred budget, without separate rooms.

Illustrative wording. Live questions and explanations can vary.

We leave priority undecided, then answer the specialist's question. Only the requested field can change during continuation. The answer keeps the same task ID and context ID. A missing budget can trigger an earlier question, so one task can need more than one clarification. Changing preferences between runs is more informative than repeatedly running an identical brief.

Rehearsal and Live AI

Rehearsal Live AI
Decisions Explicit rules Model calls with separate agent prompts
A2A transport Real local HTTP exchanges Real local HTTP exchanges
Preferences Ranks by selected priority Also interprets free-text preferences
Use in class Repeatable protocol walkthrough Observe decisions and evaluate explanations

The same recommendation can be correct in both modes. Matching outputs alone do not prove model autonomy.

A2A is the communication protocol, not the reasoning engine. Live AI has no scripted fallback. Connection errors remain errors. Evidence comes from the selected mode, observed provider calls, actual transport and whether the decisions respond to the brief. A different answer is not automatically better. Source: docs/ARCHITECTURE.md.

Delegation still needs review

A completed task can contain a wrong explanation.

The first quiet-room run chose Cedar Room correctly, but described AED 1,350 as above the AED 1,400 preferred budget.

  1. Code checks factsCanonical prices, constraints and budget arithmetic
  2. Coordinator reviewsAccept, request one revision, or reject
  3. Revisions stay boundedA new linked task in the same context, at most once

Linked revisions are verified with model fixtures. A live model-requested revision has not been observed.

The correction supplies computed budget facts to the reviewer and screens a narrow class of above/below-preferred-budget contradictions. It is not a general fact checker. Code-triggered corrections are labelled separately from model requests. A completed task cannot be reopened, so revision creates a new task linked by referenceTaskIds. Clarification, by contrast, continues the existing task. Sources: src/domain/budget-review.mjs, src/agents/coordinator.mjs and docs/VALIDATION.md.

The classroom demonstration

  1. Select Discuss the trade-off and choose Rehearsal or configured Live AI.
  2. Start the handoff. Open the inspector and identify the Agent Card and task ID.
  3. Answer Separate breakout rooms. Check the artifact, cost and review.
  4. Start a new run with Prioritize a quiet room. Compare the reasoning and result.
  5. Try A budget that cannot work. Explain why rejection is a valid outcome.

Live AI uses API billing. Rehearsal remains available if the provider cannot be reached.

Keep the maximum at AED 1,600 and preferred budget at AED 1,400 for the first comparison. Use a new run to change the priority. If the live model takes a different valid path, discuss the actual evidence rather than claiming the slide predicted it. If the API fails, explicitly switch to Rehearsal and identify it as scripted decisions over real local A2A transport. Never claim an automatic fallback.

The course takeaway

A tool performs an operation.
An agent takes on a task.

Delegation adds decisions, questions and responsibility.
A2A gives those exchanges a common protocol.

Explain the discovery, the task identity, the clarification and the returned artifact.

Ask the class: if the specialist asks a question, has the task failed? No. Clarification is part of the delegated job. Then ask: does a completed task guarantee a correct result? No. Our budget explanation error is a concrete example. The coordinator still has to evaluate what comes back. End by opening the repository or the VitePress guide for questions.
