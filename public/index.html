THE EXPLANATION

Operations vs. responsibility.

Two complementary protocols. Two different kinds of handoff.

01 / MCP

“Run this operation.”

An agent calls a tool with defined inputs and receives its output.

Agent→ MCP →Tool
lookup_venues(capacity=30)

The agent chooses the operation. The tool implements that capability. Tools can contain AI, too.

02 / A2A

“Take on this goal.”

An agent gives a specialist a task and the context needed to work on it.

Agent↔ A2A ↔Agent
Recommend a venue that fits our workshop.

The specialist chooses its approach, can request more input, and returns an artifact for review.

THE FOUR THINGS TO WATCH

Follow the responsibility.

  1. Discover the specialist

    An Agent Card describes skills, endpoints, protocol support, and any authentication requirements. Here, the coordinator knows the specialist’s base URL.

  2. Describe the task

    Send a goal, context, constraints, and the expected result. The receiving service creates a task ID; a context ID groups the conversation.

  3. Allow a decision

    The specialist may need clarification, call its own tools, or report that the task cannot be done. Missing information should not become a guess.

  4. Review the return

    The specialist returns an artifact. The coordinator checks capacity, facilities, and the hard spending limit. In live mode it also reviews the trade-off and may request one revision before delivering its answer. Protocol success alone is not proof of correctness.

WHAT THIS LAB ACTUALLY DOES

Know what you’re showing.

  • Real local A2A trafficOfficial SDK, Agent Card discovery, SendMessage, GetTask, and CancelTask over HTTP.
  • Two decision modesRehearsal follows code-defined rules. Live AI uses separate coordinator and specialist instructions with the configured model.
  • A local toolThe specialist calls a catalogue function. MCP is explained here, but no live MCP server is implemented.
  • A bounded classroom demoTwo HTTP services in one Node process. One local operator, fictional data, in-memory tasks, and no cross-company deployment or booking.
